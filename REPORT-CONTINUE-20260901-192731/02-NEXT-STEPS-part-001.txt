ПЛАН ПРОВЕРКИ ПОСЛЕ СБОРКИ 3

ШАГ 1. ПРОВЕРКА ПРОГРАММЫ

Запустить:

publish-build3\TextFileProcessor.exe

Убедиться, что программа открывается без ошибки и присутствуют вкладки:
— создание/обработка сайтов;
— ISPmanager;
— SSH/SFTP;
— Задания;
— журнал, если он предусмотрен интерфейсом.

ШАГ 2. ПРОВЕРКА SSH/SFTP

Во вкладке SSH/SFTP:
1. Проверить адрес сервера.
2. Проверить SSH-порт.
3. Проверить SSH-пользователя.
4. Убедиться, что сохранён правильный Host key SHA-256.
5. Нажать «Проверить подключение».

Fingerprint должен совпадать со значением, независимо полученным
в терминале сервера. Нельзя подтверждать неизвестный fingerprint.

ШАГ 3. ТЕСТОВЫЙ САЙТ

1. Создать один тестовый домен.
2. Дождаться успешного завершения локальной генерации.
3. Убедиться, что OutputPath существует.
4. Проверить содержимое локальной папки.
5. Выбрать задание в таблице.
6. Нажать «Загрузить выбранный сайт».
7. Подтвердить загрузку.

Ожидаемый удалённый путь:

/var/www/www-root/data/www/ИМЯ-ДОМЕНА/

Не должно получиться:

/var/www/www-root/data/www/ИМЯ-ДОМЕНА/ИМЯ-ДОМЕНА/

ШАГ 4. ПРОВЕРКА НА СЕРВЕРЕ

В терминале ISPmanager выполнить, заменив example.com:

find /var/www/www-root/data/www/example.com \
  -maxdepth 2 -type f -printf '%u:%g %m %p\n' | head -100

Проверить отсутствие SQL-файлов в web-root:

find /var/www/www-root/data/www/example.com \
  -type f -iname '*.sql' -print

Вторая команда не должна показать загруженные SQL-файлы.

Проверить владельца каталога:

stat /var/www/www-root/data/www/example.com

Ожидаемые владелец и группа:

www-root:www-root

ШАГ 5. ПРОВЕРКА САЙТА

1. Открыть HTTP-адрес домена.
2. Открыть HTTPS-адрес домена.
3. Проверить сертификат.
4. Проверить главную страницу.
5. Проверить внутренние ссылки.
6. Проверить CSS, JavaScript и изображения.
7. Проверить PHP, если он используется.
8. Проверить подключение к базе данных.
9. Проверить журнал ошибок сайта.
10. Проверить мобильное отображение.

ШАГ 6. ЕСЛИ ЗАГРУЗКА НЕ РАБОТАЕТ

Зафиксировать:
— полный текст ошибки без пароля;
— на каком проценте произошла ошибка;
— имя тестового домена;
— локальный OutputPath;
— удалённый каталог;
— результат проверки подключения;
— результат команды sshd -T;
— права удалённого каталога;
— последние сообщения журнала приложения.

Не публиковать:
— SSH-пароль;
— приватные SSH-ключи;
— API-ключи;
— пароли баз данных;
— cookie и токены авторизации.

СЛЕДУЮЩАЯ РАЗРАБОТКА

После успешного теста Сборки 3 можно планировать:
— пакетную загрузку нескольких сайтов;
— отмену длительной загрузки;
— повторную загрузку только изменённых файлов;
— резервное копирование удалённого сайта;
— удаление устаревших файлов только с отдельным подтверждением;
— переход с пароля SSH на отдельный ключ;
— отдельного ограниченного пользователя вместо root;
— журнал развёртываний;
— автоматическую проверку сайта после публикации.
