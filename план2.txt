## Этапы разработки

1. **Сборка 1:** интерфейс, домены, копирование, замены, `config.php`, поиск SQL, SQLite и журнал.
2. **Сборка 2:** Playwright и создание WWW-домена в ISPmanager.
3. **Сборка 3:** SSH/SFTP, загрузка содержимого папки без лишнего уровня.
4. **Сборка 4:** создание БД, пользователя и импорт обработанного SQL.
5. **Сборка 5:** получение двух ACME TXT и Spaceship API.
6. **Сборка 6:** DNS-проверка, завершение SSL, восстановление после перезапуска и публикация.


Итог:

```text
/var/www/www-root/data/www/1234.ru/index.php
/var/www/www-root/data/www/1234.ru/config/config.php
```

# 7. Правила замен

Для каждого задания:

```text
Искомый текст №1 → домен
Искомый текст №2 → соответствующее значение поля №2
```

Замена №2 выполняется только при наличии обоих значений:

```text
Искомый текст №2 заполнен
Значение №2 для домена заполнено
```

По умолчанию обрабатываются:

```text
.php
.html
.htm
.txt
.sql
```

Дополнительно можно включить:

```text
.css
.js
.json
.xml
.env
.ini
.conf
```

Даже при разрешённом расширении файл сначала проверяется на признаки бинарного содержимого.

После этого основой будет **Сборка 1**: полноценный интерфейс и локальная обработка сайтов. Все дальнейшие файлы создаются в новом проекте — никаких старых исходников не предполагается.
Уточнение принято. Для каждого домена создаётся **одна отдельная папка с именем домена**, а на сервер переносится **содержимое этой папки**, без дополнительного вложенного каталога.

## Пример локальной структуры

Для списка:

```text
1234.ru
5678.ru
```

результат будет:

```text
ПапкаРезультата\
├── 1234.ru\
│ ├── index.php
│ ├── config\
│ │ └── config.php
│ ├── assets\
│ └── database.sql
│
└── 5678.ru\
 ├── index.php
 ├── config\
 │ └── config.php
 ├── assets\
 └── database.sql
```

Не должно получиться лишнего уровня:

```text
ПапкаРезультата\1234.ru\1234.ru\...
```

Программа копирует **содержимое выбранного корня исходного сайта** непосредственно в создаваемую папку домена.

Перед запуском будет показан предварительный результат:

```text
Исходный корень:
C:\...\Исходная папка\96377.cfd\96377.cfd\

Конечный корень:
C:\...\Результат\1234.ru\

Стартовый файл:
C:\...\Результат\1234.ru\index.php

Конфигурация:
C:\...\Результат\1234.ru\config\config.php
```

Это позволит обнаружить ошибочно выбранный внешний уровень папки до копирования.

## Временные и конечные папки

Во время обработки используются временные каталоги:

```text
ПапкаРезультата\.processing-1234.ru-<ID>\
ПапкаРезультата\.processing-5678.ru-<ID>\
```

После успешного копирования и замен они атомарно переименовываются:

```text
.processing-1234.ru-<ID> → 1234.ru
.processing-5678.ru-<ID> → 5678.ru
```

Количество конечных папок строго соответствует количеству уникальных доменов.

---

# `config.php`

В каждой готовой папке будет свой обработанный `config.php`:

```text
1234.ru\config\config.php
5678.ru\config\config.php
```

После замен программа отдельно читает из каждого файла:

```php
'name' => '...',
'user' => '...',
'pass' => '...',
```

Зафиксированное правило:

- `name` — уникальное значение для каждого домена;
- `user` — уникальное значение для каждого домена;
- `pass` — одинаковый пароль во всех обработанных конфигурациях;
- чтение выполняется только после всех замен;
- исходный `config.php` не используется для создания базы;
- пароль не записывается в журнал и SQLite.

Перед созданием базы программа проверит отсутствие повторов `name` и `user` между заданиями. Если обнаружится совпадение, массовый запуск будет заблокирован.

# Размещение на сервере

Для домена `1234.ru` итоговая структура должна быть:

```text
/var/www/www-root/data/www/1234.ru/
├── index.php
├── config/
│ └── config.php
├── assets/
└── остальные файлы и папки сайта
```

Лишнего вложения быть не должно:

```text
/var/www/www-root/data/www/1234.ru/1234.ru/
```

То есть SFTP передаёт не сам локальный каталог как дополнительную папку, а его содержимое:

```text
Локально:
C:\Результат\1234.ru\*

На сервер:
 /var/www/www-root/data/www/1234.ru/
```

## Безопасное развёртывание

ISPmanager сначала создаёт:

```text
/var/www/www-root/data/www/1234.ru/
```

Затем программа:

1. Загружает содержимое локальной папки во временный серверный каталог:

```text
/var/www/www-root/data/www/.upload-1234.ru-<ID>/
```

2. Проверяет количество и размеры файлов.
3. Временно переименовывает каталог, созданный ISPmanager:

```text
1234.ru → .backup-1234.ru-<ID>
```

4. Переименовывает загруженный каталог:

```text
.upload-1234.ru-<ID> → 1234.ru
```

5. Устанавливает владельца и группу:

```text
www-root:www-root
```

6. Проверяет стартовую страницу.
7. При ошибке возвращает резервную папку.

В результате файлы сразу находятся внутри:

```text
/var/www/www-root/data/www/1234.ru/
```

## Обработка SQL-файла

Обработанный SQL используется для импорта, но оставлять дамп в публичной папке небезопасно. Поэтому по умолчанию:

- SQL определяется в локальной обработанной копии;
- передаётся во временный закрытый каталог вне web-root либо импортируется через защищённый механизм ISPmanager;
- после импорта временная серверная копия удаляется;
- в публичном каталоге сайта `.sql` не остаётся.

При этом локальный обработанный SQL сохраняется в:

```text
C:\Результат\1234.ru\...
```

для резервного восстановления.

# Окончательный порядок обработки

Для каждого домена строго последовательно:

1. Создать отдельную временную локальную папку задания:

 ```text
 .processing-1234.ru-<ID>
 ```

2. Скопировать в неё **содержимое выбранного корня исходного сайта**.

3. Выполнить замены во всех разрешённых текстовых файлах.

4. Проверить:
 - результаты замен;
 - наличие стартовой страницы;
 - структуру каталогов;
 - отсутствие лишнего уровня `1234.ru\1234.ru`.

5. Переименовать временную папку в:

 ```text
 1234.ru
 ```

6. Найти `config.php` в конечной обработанной копии.

7. Прочитать обработанные `name`, `user` и `pass`.

8. Найти или выбрать SQL-файл в обработанной копии.

9. Создать WWW-домен в ISPmanager:

 ```text
 domain: 1234.ru
 aliases: www.1234.ru *.1234.ru
 owner: www-root
 PHP: 8.3.8
 ```

10. Создать уникальные базу и пользователя.

11. Загрузить содержимое локальной папки:

 ```text
 C:\Результат\1234.ru\*
 ```

 непосредственно в:

 ```text
 /var/www/www-root/data/www/1234.ru/
 ```

12. Импортировать обработанный SQL-файл в созданную базу.

13. Запросить обязательный сертификат для:

 ```text
 1234.ru
 *.1234.ru
 ```

14. Получить два ACME TXT-значения.

15. Добавить оба TXT через Spaceship API, не изменяя остальные DNS-записи.

16. Проверить оба TXT через авторитетные NS, Cloudflare DNS и Google DNS.

17. Продолжить выпуск сертификата в ISPmanager.

18. Проверить SAN сертификата, HTTPS и перенаправление HTTP → HTTPS.

Понял уточнение. SQL-файл — это дамп с данными, а реквизиты для создания новой БД находятся в config.php. Поэтому базу в ISPmanager всё-таки нужно сначала создать, а затем загрузить в неё SQL.

Для домена casino71.cfd правильный порядок такой:

В готовой папке найти файл:

C:\Users\User\Desktop\Adminki\. Программа домены\работа\Результат\casino71.cfd\config\config.php

Прочитать из обработанного config.php:

'name' => 'имя_базы',
'user' => 'пользователь_базы',
'pass' => 'пароль_базы',

В ISPmanager через db.edit создать БД с этими реквизитами:

Имя БД — значение name;
Пользователь БД — значение user;
Пароль — значение pass.
Найти один обработанный файл:

*.sql

во всей папке:

C:\Users\User\Desktop\Adminki\. Программа домены\работа\Результат\casino71.cfd\

После появления созданной БД в списке ISPmanager вызвать для неё:

db.upload

Загрузить найденный SQL-дамп в созданную БД.

Правильная схема:

config\config.php
        ↓
name + user + pass
        ↓
создание БД в ISPmanager
        ↓
поиск *.sql в готовой папке домена
        ↓
db.upload
        ↓
импорт SQL в созданную БД

Важные правила:

имя, пользователь и пароль не берутся из названия SQL-файла;
SQL-файл сам по себе не создаёт запись БД в панели;
используется только обработанный config.php из готовой папки домена;
пароль не записывается в SQLite и журнал;

SQL не загружается в публичную папку сайта;
после импорта временная серверная копия SQL удаляется.
Таким образом, прежнее указание «БД создавать не нужно» отменяется: БД создаётся по реквизитам из config.php, а её содержимое загружается из *.sql.

из обработанного config.php прочитать name, user, pass;
создать в ISPmanager новую БД с этими реквизитами;
найти *.sql в папке готового домена;
